# SNAP ABAWD screening: decision specification

What the screening decides, and on what input. Generated by running the engine, so it
describes real behaviour rather than intended behaviour.

This is not legal review. It says what the code does. Whether that matches Massachusetts
SNAP policy is the open question, and the Citation column in the tables below is where an
expert records the authority for each rule. Every row is currently blank.

Companion file `decision-spec.json` holds the same structure for a port to generate from.

## The three outcomes, and which one wins

| Input | Outcome |
|---|---|
| An exemption applies, and a good cause reason is also given | `exempt` |
| No exemption, good cause given | `goodcause` |
| No exemption, good cause explicitly none | `notexempt` |
| Nothing answered at all | `notexempt` |

So the order is: exemption first, then good cause, then not exempt.

`exempt` skips the good cause question entirely, because it cannot change the outcome:

| Outcome | Good cause question asked |
|---|---|
| exempt | no |
| notexempt so far | yes |

## Work and income

One question, pick one. All three options lead to exempt, by two different routes.

| Option | Label | Exempt | Reason recorded | Citation |
|---|---|---|---|---|
| `income_weekly` | Yes, I am making $217.50 a week or more (before taxes) | yes | I earn enough money from work to be exempt from the work rules | |
| `hours_min_wage` | Yes, I am working at least 14.5 hours a week at $15 or more an hour | yes | I earn enough money from work to be exempt from the work rules | |
| `hours_30` | Yes, I am working 30 hours or more a week (I make less than minimum wage) | yes | I work 30 or more hours a week while earning less than minimum wage | |
| none of these | None of the above | no | none | |

Worth an expert's attention: `hours_30` means 30 or more hours a week while earning
*less* than minimum wage, and it currently routes to exempt on its own. Whether that is
right is an open question already recorded in README.md.

## Housing, and the unable-to-work follow-up

This is the only branch whose behaviour is hard to predict by reading it, so every
possible input is enumerated below rather than summarised.

The follow-up is only asked when `housing` is answered "no", meaning no regular place to
sleep. Answering "yes" to `housing` never produces an exemption:

- `housing` = yes: not exempt
- `housing` = no, follow-up not answered: not exempt

The follow-up options describe things that suggest someone *can* work, so the logic is
inverted: lacking them is what points to an exemption.

Option ids, in the order shown: `diploma`, `ongoing_care`, `steady_job`, `full_time_student`, `hospitalized`.

In words: someone with no regular place to sleep is treated as possibly unable to work
unless they checked a high school diploma **and** either a steady job or full-time study,
**and** checked neither hospitalisation nor ongoing care. Checking nothing at all is
treated as unanswered, not as "none apply".

That description was checked against all 32 rows above and agrees with every one.

Two things for an expert here. The empty selection and the explicit "none of these"
option produce opposite results, which is correct but easy to misread. And this branch
records a reason asking DTA to review, rather than asserting an exemption outright.

## Good cause

Asked only when the answers so far point to neither an exemption nor the age outcome.
Pick one.

| Option | Outcome | Citation |
|---|---|---|
| `transport` | `goodcause` | |
| `emergency` | `goodcause` | |
| `employment` | `goodcause` | |
| *none of these* | `notexempt` | |

Good cause never produces an exemption. It produces a different result screen, and a
different printable statement.

## Question flow

Sixteen questions in four groups, every one optional, then the good cause question.

**Group 1: Your Family and Household**

- `ageRange` (yn)
- `child14` (yn, exempts on "yes")
- `child6` (yn, exempts on "yes")
- `caretaker` (yn, exempts on "yes")
- `pregnant` (yn, exempts on "yes")

**Group 2: Your health, housing, and safety**

- `health` (yn, exempts on "yes")
- `housing` (yn)
- `housingFollowup` (multi, only if `housing` = "no")
- `dv` (yn, exempts on "yes")

**Group 3: Public Benefits and Participating in Programs**

- `tafdc` (yn, exempts on "yes")
- `disability` (multi)
- `substanceUse` (yn, exempts on "yes")
- `unemployment` (yn, exempts on "yes")
- `stateagency` (multi)

**Group 4: School, work, and background**

- `school` (yn, exempts on "yes")
- `working` (single)
- `tribe` (yn, exempts on "yes")

Only one question is conditional: `housingFollowup`, shown when `housing` is "no".
Everything else is always shown, and may be left blank.

## Numbers, and who has to confirm them

| Value | Currently | Citation |
|---|---|---|
| Weekly earnings that exempt | $217.50 before taxes | |
| Massachusetts minimum wage | $15 an hour | |
| Hours a week at minimum wage that exempt | 14.5 | |
| Hours a week counted below minimum wage | 30 | |
| Age the rules apply to | 18 through 64 | |

Confirmed August 2026 against MLRI’s SNAP Advocacy Guide, May 2026, Part 2, Question 61, which gives $217.50 a week, 14.5 hours a week at $15 an hour, and 30 or more hours a week for someone earning below minimum wage. A copy is in reference/ in the repository.

So the numbers are settled. What is not settled is the housing branch below, where the same
guide says the follow-up answers are not an automatic exemption in either direction.

The age wording was settled on 2026-08-03. The article says "between 18 and 65", which
does not say whether a 65-year-old is included, and the federal rule caps at 64 with 65
and over exempt by age. The screener says "18 through 64" to state that range without
ambiguity. Worth confirming that reading of the rule.

## Notes for the Docassemble port

Structural mismatches to plan around, rather than discover.

Docassemble asks for a variable when something needs it. This screening asks everything
up front in groups and lets any of it stay blank. A group maps to one `question` block
with several `fields`, each `required: False`, which keeps them defined so the decision
code never triggers a question of its own.

The none-of-these sentinel is a real value here, `__none`, and it is not the same as
unanswered. The housing table above shows the two producing opposite outcomes. A port
using an empty checkbox set for both would be wrong.

Answers persist in the browser for 24 hours and nothing is transmitted. On a Docassemble
server they become session data under the host's retention policy. That is a change in
what the tool can honestly claim, not just where it runs.

The printable statement is generated in the browser today. It maps onto an `ALDocument`
from a DOCX template, and filling DTA's own self-declaration PDF would fit the Assembly
Line pipeline better than generating a letter.

The big Yes/No tiles are a deliberate departure from stock Docassemble question screens.
Preserving them means custom CSS in the package, not the default question library.
